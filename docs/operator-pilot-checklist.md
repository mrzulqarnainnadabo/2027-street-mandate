# Operator pilot checklist — response tracking

Use **after** mandates are `Published`. Fields below are **Notion operator-only**. Do not build public UI for them until this pilot is reviewed.

## Response-tracking fields (already on the live DB)

| Field | Use |
|-------|-----|
| Responsible Institution | Specific body when known (not a substitute for Office) |
| Response Requested | Date ISEYC actually requested a response |
| Response Received | Date a response was received |
| Follow-up Date | Next planned review |
| Resolution Status | Not assessed / Open / Partly addressed / Addressed / Unresolved |
| Response Evidence | Official URL only |

## Sequence

1. Confirm `Status = Published` (do not change Status while tracking).
2. Fill Responsible Institution only when identifiable.
3. Set dates only when events actually happened.
4. Keep Resolution Status honest; prefer Not assessed until rules are agreed.
5. Evidence URLs must be official, relevant, and safe for operators.

## Five-record pilot

Select five Published rows. Document decisions. Exit when the team has written rules for acknowledgement vs delivery, partial address, and who may mark Addressed/Unresolved.

See also: `docs/mandate-to-response-protocol.md` and `docs/public-data-boundary.md`.
