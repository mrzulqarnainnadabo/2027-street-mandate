# Operator pilot checklist — response tracking

Use **after** mandates are `Published`. Fields below are **Notion operator-only**.

**Governance (Decision Register):**

- **D-03** — Institutional responses remain **private by default**. Do not expose private correspondence, internal notes, staff comments, or unresolved assessments on public surfaces. A public response requires an explicit publication decision plus evidence/provenance (not built yet).
- **D-04** — Recusal: see `docs/governance/reviewer-recusal-sop.md` (draft SOP).

Do not build public UI for response fields until founder authorises that surface.

## Response-tracking fields (already on the live DB)

| Field | Use |
|-------|-----|
| Responsible Institution | Specific body when known (not a substitute for Office) |
| Response Requested | Date ISEYC actually requested a response |
| Response Received | Date a response was received |
| Follow-up Date | Next planned review |
| Resolution Status | Not assessed / Open / Partly addressed / Addressed / Unresolved |
| Response Evidence | Official URL only |

## Sequence

1. Confirm `Status = Published` (do not change Status while tracking).
2. If you have a conflict on this record, **recuse** (D-04) and hand to another reviewer.
3. Fill Responsible Institution only when identifiable.
4. Set dates only when events actually happened.
5. Keep Resolution Status honest; prefer Not assessed until rules are agreed.
6. Evidence URLs must be official, relevant, and safe for operators.
7. Keep all of the above **off** public Pulse/Brief/mandate pages.

## Five-record pilot

Select five Published rows. Document decisions. Exit when the team has written rules for acknowledgement vs delivery, partial address, and who may mark Addressed/Unresolved.
